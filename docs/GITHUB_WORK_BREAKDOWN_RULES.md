# GitHub Work Breakdown Rules

## Required

The Planner must use GitHub hierarchy where supported:

```text
Epic
└── Feature
    └── User Story
        └── Task
```

## Creation rules

### Epic

One major outcome for the current product scope.

### Feature

A cohesive capability.

### User Story

A user/system outcome that can be independently validated.

### Task

A bounded engineering action.

## Status

New work:

`Backlog`

First task may become:

`Ready`

only after planning gates pass.

## Avoid

- duplicate work items
- speculative future features
- implementation trivia as separate Stories
- administrative tasks disguised as product work
