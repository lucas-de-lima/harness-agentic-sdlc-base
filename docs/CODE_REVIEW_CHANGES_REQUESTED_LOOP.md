# Changes Requested Loop

When review returns `Changes Requested`:

1. Reviewer records each actionable finding.
2. Task moves to `In Progress`.
3. Go Engineer receives the findings.
4. Engineer modifies only the affected scope.
5. Engineer re-runs validation.
6. Engineer produces a new Handoff.
7. Task returns to `In Review`.
8. Code Review runs again.

The second review must verify the fixes rather than assume they are correct.
