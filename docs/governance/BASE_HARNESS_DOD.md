# Base Harness Definition of Done

The Base Harness is considered complete enough for pilot use when:

## Governance

- [ ] Constitution approved.
- [ ] Taxonomy approved.
- [ ] Architecture catalog approved.
- [ ] Go engineering standards approved.
- [ ] Skill specification approved.
- [ ] Agent contract approved.
- [ ] Workflow contract approved.
- [ ] Tool/MCP policy approved.

## Runtime

- [ ] Canonical Base skills exist.
- [ ] Codex runtime projection exists.
- [ ] Base validation is executable.
- [ ] Harness Factory is executable.
- [ ] Dedicated Harness validation is executable.

## SDLC

- [ ] Discovery workflow exists.
- [ ] Architecture workflow exists.
- [ ] Architecture review exists.
- [ ] Planning exists.
- [ ] Implementation exists.
- [ ] Code review exists.
- [ ] Release gates exist.

## Safety

- [ ] Agent authority is bounded.
- [ ] No reviewer edits what it reviews.
- [ ] Architecture changes require architecture workflow.
- [ ] Work state is represented in GitHub.
- [ ] Autonomous loops have bounded termination.

## Pilot readiness

- [ ] A real project can receive a Dedicated Harness.
- [ ] A real first Task can traverse the full lifecycle.
- [ ] Base changes are versioned and reproducible.
