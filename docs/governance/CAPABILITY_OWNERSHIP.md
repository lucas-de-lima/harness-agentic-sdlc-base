# Capability Ownership

## Base Harness owns

- governance
- architecture catalog
- pattern catalog
- Go standards
- reusable skills
- reusable agent contracts
- workflow contracts
- tool/MCP policies
- Harness Factory
- validation tooling
- templates

## Dedicated Harness owns

- project profile
- selected architecture
- selected capabilities
- project-specific skills
- project-specific policies
- project-specific workflows
- project-specific tool policy
- domain context

## Product repository owns

- application code
- tests
- runtime configuration
- infrastructure required by the product
- durable product documentation

## GitHub owns

- operational work items
- status
- hierarchy
- project fields
- execution comments
- PR relationships

## Principle

Do not move a capability upward into the Base merely because one project needs it.
Promote it only after it is demonstrably reusable.
