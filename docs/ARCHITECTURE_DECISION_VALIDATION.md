# Architecture Decision Validation

## Required

- selected architecture
- confidence
- context
- candidates
- simplicity baseline
- rationale
- rejected alternatives
- consequences
- future pressure
- unresolved questions

## Quality checks

### Evidence
Every major rationale claim must trace to Project Profile evidence or an explicitly stated assumption.

### Simplicity
The simplest viable architecture must be explicitly named.

### Alternatives
At least one meaningful alternative must be considered when more than one candidate is plausible.

### Scope
Do not present implementation details as architecture unless they materially constrain the system.

### Evolution
A future trigger must be described whenever the selected architecture intentionally avoids a more complex option.
